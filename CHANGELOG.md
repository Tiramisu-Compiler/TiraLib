# Changelog

## 0.2.0

### Added

- Measurement harness abstraction (`tiralib.tiramisu.harness`): the
  wrapper that measures execution times is now generated by a
  pluggable `Harness` object.
  - `DefaultHarness`: the historical behavior, unchanged (random
    constant init, warm in-process timing loop).
  - `PolybenchHarness`: PolyBench/C 4.2.1 measurement methodology for
    PolyBench-derived programs — deterministic `init_array`
    initialization from a per-benchmark init sidecar, page-aligned
    allocation, cache flush before the timer, `gettimeofday` timing,
    one kernel invocation per fresh process. Uses the vendored,
    unmodified `polybench.{c,h}` (in `tiralib/tiramisu/polybench/`).
    Works with both execution backends (CompilingService and the
    TiraLibCpp server) without backend changes.
- Harness auto-detection in `TiramisuProgram.from_file`: a
  `<function_name>_init.h` sidecar next to the generator file selects
  the `PolybenchHarness`; `harness=` parameters on `from_file`,
  `init_server`, and `from_annotations` override.
- `PolybenchHarness.from_code` for sidecars sourced from archives.
- `polybench_normalized_time`: PolyBench `time_benchmark.sh` statistic
  (drop min and max, mean of the middle runs).
- `TIRALIB_DUMP_ARRAYS=1` makes PolyBench-harness wrappers dump the
  live-out arrays to stderr in PolyBench's `POLYBENCH_DUMP_ARRAYS`
  format, enabling numerical comparison against PolyBench/C.
- `TiramisuProgram.buffer_types`: per-buffer element types parsed from
  the generator (`p_float64`/`p_float32`/`p_int32`); the PolyBench
  harness allocates buffers with the correct types.

Benchmarks with sidecars, their generator, and the validation of the
harness against stock PolyBench/C live in the
[polybench-tiramisu](https://github.com/Mascinissa/polybench-tiramisu)
repository.

### Fixed

- Buffer declaration parsing now anchors on the buffer name, so a
  buffer named `b_A` can no longer pick up the declaration of `b_AB`.
